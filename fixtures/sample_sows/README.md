# fixtures/sample_sows/

Deterministic sample SOWs for the SOW-first pipeline (Sprint 9 wave 2).

Every PDF here is generated by [`generate.py`](./generate.py) from the
canonical extraction stubs in [`extraction_stubs.py`](./extraction_stubs.py).
The bytes are stable across runs — the E2E suite hashes them to prove
the fixtures did not drift.

## Regenerate

```
cd api && . .venv/bin/activate
python ../fixtures/sample_sows/generate.py            # rebuild PDFs
python ../fixtures/sample_sows/generate.py --hash     # + print sha256
python ../fixtures/sample_sows/generate.py --validate # + run schema check
```

`reportlab` is listed under `[project.optional-dependencies].dev` in
`api/pyproject.toml`; install with `pip install -e '.[dev]'`.

## Validate

```
cd api && . .venv/bin/activate
pytest ../fixtures/sample_sows/test_extraction_stubs.py -q
```

The pytest asserts that every stub (a) matches the Bedrock JSON schema
in `app.integrations.bedrock_sow_extract.validate_extract`, (b) drives
`app.services.engagement_classifier.classify` to the declared
engagement type via the declared rule id, (c) has a PDF on disk, and
(d) the generator produces the exact same bytes recorded on disk.

## E2E integration

The TypeScript E2E layer consumes [`extraction_stubs.json`](./extraction_stubs.json)
(auto-emitted by `generate.py`). The seed helper `seedFixtureSow(name)` in
`tests/e2e/fixtures/seed.ts`:

1. Creates a SOW version via the normal upload flow.
2. Patches every extracted field with the value from
   `extraction_stubs.json[<name>]["fields"]` so the confirmation
   endpoint sees the canonical payload.
3. Also patches the auxiliary hints (`resource_table`, `monthly_fee`,
   `coverage_hours`, `primary_location`, …) that the classifier and
   auto-staffing service key on.

This lets the E2E specs drive the pipeline end-to-end without a live
Bedrock call and without depending on any specific bytes surviving OCR.

## Constraints (CLAUDE.md rule 8)

- No real client data — every name and dollar figure is synthetic.
- Deterministic — regeneration produces byte-identical PDFs.
- The generator pins `SOURCE_DATE_EPOCH=1735689600` and passes
  `invariant=1` to reportlab so the PDF trailer / doc id is fixed.
