## Changes made to the external branch (and why)

Three commits added on top of the branch author's `2095a24 feat: add
S13b Finance GM panel and direct costs`, each strictly a merge-hygiene
fix — no product code changed:

1. **`fcaf515 S13b merge fix: chain direct-cost migrations after archived_at`**
   The rebase left two Alembic heads both chained to `20260923_0032`
   (`20260924_0033_archived_at` from S13a, `0033_direct_costs` from the
   branch). Renamed the branch's migrations to chain after S13a:
   - `20260924_0033_direct_costs.py` → `20260924_0034_direct_costs.py`
     (revision `20260924_0034_direct_costs`, down `20260924_0033`)
   - `20260924_0034_direct_cost_settings.py` →
     `20260924_0035_dc_settings.py`
   Verified single head via `ScriptDirectory.get_heads()`.

2. **`897a824 S13b merge fix: shorten dc_settings revision`**
   The first-attempt rename made the second revision string 34 chars.
   `alembic_version.version_num` is `VARCHAR(32)`; the RDS `UPDATE
   alembic_version SET version_num='20260924_0035_direct_cost_settings'`
   failed with `StringDataRightTruncation`. Shortened to
   `20260924_0035_dc_settings` (25 chars). Chain now:
   `20260924_0033 → 20260924_0034_direct_costs → 20260924_0035_dc_settings`.

3. **Merge conflict resolutions (in the rebase commit itself)**:
   - `docs/directives/s13b-gm-panel.md` — add/add, both sides identical.
     Kept main's version.
   - `web/src/__tests__/v2/StaffingGmSection.test.tsx` — add/add. Branch
     wins (S13b test surface).
   - `web/src/pages/v2/sow-studio/confirmation/StaffingGmSection.tsx` —
     content conflict. Branch wins (S13b UI component).
   - `web/src/pages/v2/sow-workspace/format.ts` — content conflict. Main
     wins on the shared formatter (kept `formatUsd(value, digits?)` +
     `formatPercent(digits=1)`) but the branch's additions
     (`formatRate`, `formatQuantity`, `decimalInput`) were merged in
     manually because the branch's new UI code depends on them.

No S13a infrastructure was lost in the rebase:
