Note: `cache-control: no-store` is now on every 4xx/5xx API response.
CloudFront still masquerades some 4xx codes as SPA HTML because the
`/api/*` cache behavior still uses the distribution-wide
`custom_error_response` map — that fix ships in step 3 with the TF
apply. The middleware header is a defence-in-depth: even when a
future caller or proxy sees the origin's real response, it can't
cache the error.

The `apiFetch` helper in `tests/e2e/fixtures/api.ts` now asserts
`content-type: application/json` on every response and fails loudly
on HTML — permanent guard against the S13a class of silent failure.
That's fixture code, so it takes effect on the next Playwright run;
no deploy needed.

## Implementation (as-authored by 31042b7)

- `infra-tf/modules/web/spa-rewrite.js` + `aws_cloudfront_function.spa_rewrite`
  on the **default** SPA behavior only. Bails out for `/api`, `/api/*`,
  `/assets/*`, and non-GET/HEAD; extensionless GETs rewrite to `/index.html`.
  Behavior-scoped, not a distribution-wide error rewrite.
- `/api` and `/api/*` are two separate ordered cache behaviors, both routed
  to `alb-api` via the existing `strip_api_prefix` function with
  `Managed-CachingDisabled`. API errors pass through with their real
  status + body.
- `custom_error_response` list rebuilt: {400, 403, 404, 405, 414, 500,
  501, 502, 503, 504} each with `error_caching_min_ttl = 0` and no
  `response_page_path` / `response_code`. This removes the S3 SPA
  fallback that S13a hit and prevents any cached API error.
- `api/app/middleware.py::ErrorCacheControlMiddleware` — adds
  `Cache-Control: no-store` on every response with status ≥ 400.
  Wired at app-construction time in `api/app/main.py`. The final
  Starlette-level exception handler for uncaught 500s also emits the
  header (Starlette's outer `ServerErrorMiddleware` runs outside user
  middleware).
- `infra-tf/modules/api/variables.tf::allow_dev_seed_endpoint` — new
  boolean, `default = false`. `infra-tf/modules/api/main.tf` conditionally
  appends `ALLOW_DEV_SEED_ENDPOINT=1` to the task-def environment ONLY
  when `env == "staging" AND allow_dev_seed_endpoint == true`.
- `infra-tf/env/staging/main.tf` sets `allow_dev_seed_endpoint = true`
  explicitly, retiring the manual task-def drift S13a introduced.
- `tests/e2e/fixtures/api.ts::apiFetch` — permanently asserts
  `content-type: application/json` on every response (except genuine
  `204/205 no-content`), fails loudly with the received status and body
  slice.
