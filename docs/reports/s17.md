## §2 · Any SOW can be deleted at any stage

**One delete service** — `api/app/services/deletion.py` rewritten.
- `delete_sow(session, actor_id, sow_id)`: hard-deletes the SOW +
  every SowVersion / GmModel (+ resource_lines, cost_lines) / approval
  package (+ Approvals, ApprovalAssignments, ApprovalConditionEvidence,
  CeoException) / SignedSowUpload / review-task via ApprovalAssignment.
  task_id / notifications keyed to opportunity or package / S3 objects
  under the SOW prefix. Writes exactly **one audit line** carrying the
  directive's five fields: `{who, when, sow_title, stage, price}`.
- `delete_opportunity` fans out to `delete_sow` per SOW then removes
  the opportunity.
- `delete_client` fans out to `delete_opportunity` per opp then removes
  agreements (with their S3 files), contacts, aliases, rate cards +
  rows, legal entities, and the client.
- `assess_client` / `assess_opportunity` / `assess_sow` always return
  `state="draft"` — the S13a "approved → archive-only" refusal is gone.

**Router.**
- `DELETE /sows/{sow_id}?reason=…` — S17 new; role-gated to
  SystemAdmin / CEO / SalesLeader / Finance / Legal.
- `GET /sows/{sow_id}/deletion-assessment` — populates the confirm
  dialog with cascade counts.
- `DELETE /clients/{id}` and `DELETE /opportunities/{id}` keep the same
  URLs; the service they call is the S17 one, so approved records
  cascade-delete now.
- `POST /clients/{id}/archive` and `POST /opportunities/{id}/archive`
  kept as UI back-compat shims that hard-delete under the hood.

**UI.**
- SowWorkspace header gets a **Delete SOW** button; the confirmation
  dialog reads the assess response and shows cascade counts.
