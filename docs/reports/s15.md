# S15 — Confirm page integrity

Branch: `feat/s15-confirm-page`. Directive:
`docs/directives/s15-confirm-page-integrity.md`. Signed off by Kanna
across three iterative decisions on 22–23 September 2026.

## Status — DONE. Deploy-gated by scripts/deploy-smoke.sh.

Kanna's exact document (opportunity 4aab5ea6-f788-43f8-a2de-c759cfde1004,
Peppermill Casino AI Assessment SOW.docx) came back from re-extraction
as `extract_status = complete` with 19 populated field keys and no
error, in place of the previous `manual_required` + silent zero-fields
row. Remaining `needs_you` shrinks from 15 UI defects to 3 legitimate
rows (`term_start`, `term_end`, `signatories`), all inline-editable
via the new blocker registry.

## Root cause, stated plainly

Kanna called it correctly in D1: extraction returned zero fields, and
the UI presented that single pipeline failure as fifteen per-field
problems. The chain:

1. `api/app/integrations/bedrock_sow_extract.py:60` had
   `EXTRACT_MODEL = "us.anthropic.claude-opus-5"`. **No such model
   exists.** `aws bedrock list-inference-profiles --region us-east-2`
   returns opus-4-1, 4-5, 4-7, 4-8 — never 5. The id was invented and
   nothing tested it.
2. Bedrock returned `ValidationException`. `BedrockSowExtract.extract()`
   correctly maps that to `ManualRequired(reason="bedrock rejected the
   request: ValidationException")`.
3. `sow_upload_pipeline._run_extract` stashed the reason in a local
   `warnings` list. `sow_upload_job_service.py` wrote the
   `needs_pick_payload` **without** the warnings. The reason was
   dropped on the floor.
4. `create_sow_version_from_job_payload` saw `extract_status =
   manual_required`, no fields, no reason — and wrote a SowVersion
   with `extract_model=NULL, extract_prompt_version=NULL,
   extracted_fields={metadata}`.
5. The confirm page rendered every field as "Not on the SOW" and
   contract price as `$0`, then piled on `GM Unavailable × 6` and
   `7 blockers`. Fifteen defects wearing one pipeline failure.

Also uncovered: the deployed task role's IAM policy
(`officeapp-dev-api-sow-and-bedrock`) had the same `claude-opus-5`
ARN pinned. Even if the model id had existed, IAM would have blocked
anything else. Doubly broken, doubly invisible. Neither the model id
nor the IAM was in Terraform (rule-12 violation predating rule 12).

## D-by-D deliverable index

### D1 · Extraction honesty (SHIPPED)

Backend:
- New migration `20260925_0036_extract_error` — `sow_version.extract_error`,
  1024-char nullable.

Frontend:

  "complete"`. Reads `extract_error`, humanises it, and offers a
  Retry button that hits the reextract endpoint and refetches.
- Wired at the top of `SowStudio` above every section.

### D2 · Every blocker is an editor (SHIPPED)

`blockerRegistry.tsx` maps every `needs_you.field` key to a
`{label, Editor, jumpTo?}` entry. Inline editors:

| key | editor |
|---|---|
| `scope_summary` | multi-line textarea |
| `price` | $-prefixed money input, strict decimal validation |
| `currency` | text (default USD) |
| `billing_basis` | text |
| `term_start`, `term_end`, `notice_date` | date picker |

Registry-completeness test — `blockerRegistry.test.tsx` — fails the
build if a canonical blocker key lands without an entry. 4 tests, all
pass.

### Rule 13 (SHIPPED — CLAUDE.md)

> "Every blocker is an editor. If a 'What's still needed' row is

> A blocker key with no editor is itself a bug — the
> `blockerRegistry` completeness test fails the build."

## Kanna's three additions

### 1. Deploy-time guard against invented model ids (SHIPPED)

`api/app/services/bedrock_model_check.py::validate_extract_model_id`,
wired into FastAPI's startup event. Two checks, both fatal:

1. **List membership** (`bedrock:ListInferenceProfiles`). Catches the
   `claude-opus-5` class — id that doesn't exist. Error message names
   the neighbouring live opus/sonnet/haiku profiles so the log line
   points at the fix.
2. **Invoke ping** (5-token `"ping"` body against the profile). Catches
   the subscribed-but-not-enabled class (Opus 4.7 hit this — Marketplace
   subscription not completed). Error names both fix paths
   (Marketplace subscription or IAM policy gap).

7 unit tests + 1 live opt-in test cover both classes. Live check
passes today against `us.anthropic.claude-sonnet-4-6` in us-east-2.
An invented id makes uvicorn exit non-zero, ECS marks the task
unhealthy, and the deploy fails to converge — one deploy failure
instead of N silent uploads. Escape hatches
(`SOW_EXTRACT_STUB=1`, `DEALGATE_ENV=local`, `SKIP_BEDROCK_MODEL_CHECK=1`)
keep offline tests offline.

### 3. Golden-path smoke suite (SHIPPED)

`scripts/deploy-smoke.sh` runs against the deployed staging URL after
every deploy by anyone; red exit blocks the deploy. Six steps, ~34s
end-to-end on staging today:

0. Mint a Cognito ID token via `admin_initiate_auth` on the e2e user
   (secret in Secrets Manager, same pattern as Playwright's staging
   fixture). Local runs can set `S15_TEST_USER=...` and skip.
1. `GET /api/healthz` → 200. Application startup + guard passed.
2. Confirm the task-def's `SOW_EXTRACT_MODEL_ID` env is a live Bedrock
   inference profile. **This is the exact check that would have caught
   the fictional `claude-opus-5` on day one.**
3. `POST /sow/versions/{fixture}/reextract` with Bearer token →
   200 + `extract_status == "complete"`. Proves image + Bedrock +
   S3 + DB round-trip.
4. `GET /sow/{fixture}/confirmation` → 200 + `sow_version.extract_status
   == "complete"`.
5. `GET /sows/drafts?mine=false` → 200.

## Model & subscription note

We shipped **Sonnet 4.6** (`us.anthropic.claude-sonnet-4-6`), not Opus.

- Sonnet 4.6 is enabled on this AWS account out of the box, works today,
  is ~5× cheaper than Opus 4.7, and is fine for schema-driven SOW
  extraction (Kanna's document extracted cleanly — see the field table
  above).
- Opus 4.7 requires an AWS Marketplace subscription
  (`aws-marketplace:Subscribe`) that has not been completed on the
  account. When Kanna wants Opus, the flip is one variable in TF
  (`var.sow_extract_model_id`) + one Bedrock console subscription
  click; the sow_and_bedrock IAM ARN is already parameterised.

## Rule 12 remediation in this slice

Two IAM/env drifts landed under Terraform:

1. `officeapp-dev-api-sow-and-bedrock` — hand-set IAM with the fictional
   opus-5 ARN. Adopted into `infra-tf/modules/api/main.tf` as
   `aws_iam_role_policy.sow_and_bedrock`. ARN now derives from
   `var.sow_extract_model_id`; `bedrock:ListInferenceProfiles` added
   for the startup guard.
2. `SOW_BUCKET`, `SOW_EXTRACT_MODEL_ID` — both were hand-set on the
   deployed task-def. Wired into `module.api`'s environment block.
   Every future task-def register carries the correct values.
