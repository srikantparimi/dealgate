## Follow-ups (documented, not blocking)

- **CloudFront routing gotcha.** `POST /api/**` deep-path requests
  hitting a 4xx from ALB get rewritten by the distribution's
  `CustomErrorResponses` (403/404 → `/index.html`, code 200). This
  silently masks real backend errors when tools consume the response
  status alone. Two things follow from that:
  1. The dev-seed endpoint returns `{ok: false, status, error}` with a
     literal 200 on every failure, so the caller never mistakes a 200
     HTML fallback for success. Same fix should apply to any endpoint
     whose 4xx must be distinguishable from CloudFront's fallback.
  2. Terraform ADR follow-up: tighten `CustomErrorResponses` to the S3
     cache behavior only, or set `ErrorCachingMinTTL: 0` so failed POST
     origin responses aren't cached. Track in `docs/adr/`.
- **Full approval e2e journey.** `docs/backlog/e2e-approval-journey.md`
  tracks the full four-role browser walk-through (Delivery → HR →
  Finance → Legal → CEO). The dev-seed endpoint is the interim: it lets
  the delete-refusal + archive UI be exercised end-to-end without the
  four-role plumbing.
- **`ALLOW_DEV_SEED_ENDPOINT` terraform.** The env var was added
  directly to task-def :21 via `aws ecs register-task-definition`
  (drift-tolerated by the module's `ignore_changes = [task_definition]`).
  Fold into `infra-tf/modules/api/main.tf` when the next infra PR
  touches that module so the setting survives a `terraform apply`.
