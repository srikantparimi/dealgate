## Concrete Code And Proof Gaps

1. **Manual corrections are erased on replay.** `routers/sow.py:445-479` exposes re-extraction for an existing version; its docstring explicitly says complete fields are overwritten. `services/sow_extract.py:440-482` replaces `version.extracted_fields` with a new extraction on success and blank manual fields on failure. It also clears extract model/prompt on failure. This is a static FC-09 conflict, not just absent testing. Re-extraction reads the existing file key, but no downloaded-byte-hash comparison against `SowVersion.file_hash` is performed in that endpoint.
2. **Existing override representation is reusable but not a separate retained layer.** `services/sow_extract.py:505-568` confirms a field; changed values become `provenance=manual`, accepted identical values retain extracted/looked-up/calculated/defaulted provenance, and `sow.field_confirmed` records before/after under the actor. `services/provenance.py:1-87` defines value/provenance/page_ref/source_id/confidence/warning/status, with legacy normalization. `models/sow.py:70-86` stores file hash, extract model/prompt and version-level confirmation. No dedicated override model or extraction-attempt layer was found among the reviewed models. Do not mistake legacy scalar normalization to manual provenance for proof of a confirmed human correction.
3. **Extractor terms are not the canonical seven models.** `gm/commercial.py:30-37` registers `fixed_assignment`, `recurring_msp`, `calendar_staff_aug`, `tm`, `milestone`, `unit`, `hybrid`. The compact extractor's legacy engagement labels and17 core fields plus optional direct_costs (`integrations/bedrock_sow_extract.py:94-141`) provide generic price/dates/milestones etc., not complete typed pricing components, quantities/calendar assignments, proration/usage tiers and shared-cost allocations for all seven. Existing commercial editor/calculator tests establish typed manual/canonical calculations, not automatic evidence-backed document population of every model.
4. **Strict wire shape is not evidence fidelity.** `bedrock_sow_extract.py:176-233` validates field membership/status and positive integer locators, rejecting boolean locators, but does not bind a locator to the supplied document's actual blocks or verify a cited quote/value. `document_text.py:33-35,96-110,172-235` preserves PDF pages and ordered DOCX paragraph/table blocks; Word references are block ordinals, not physical pages. Stored extracted envelopes carry page_ref without this full distinction, document hash/quote/range and attempt schema version. Numbered prompt text and parser truncation tests help but do not prove correct attribution. The model prompt already treats document text as untrusted (`bedrock_sow_extract.py:245`); no held-out adversarial outcome suite was found that demonstrates approvals/thresholds/tool behavior cannot be changed by document instructions.
5. **OCR unit routing does not cover the primary upload journey.** `test_textract_fallback.py:40-47` creates a blank one-page PDF, not a realistic scanned table. Its routing tests use StubTextract and StubBedrock through `run_extract`. The main `sow_upload_pipeline.py:621-660` reads text and invokes `_run_extract` directly; its client-bound upload counterpart also calls direct document text extraction (`sow_upload_job_service.py:580-583`). Neither path shown invokes the Textract fallback. A passed legacy `run_extract` OCR test cannot be reported as scanned-table upload acceptance.
6. **Deduplication does not implement the required extraction revision key.** `sow_upload_job_service.py:94-136,764-770` deduplicates active uploads by file hash. This avoids certain duplicate SOWs, but is not document hash + extraction/prompt/schema version replay. Existing `SowVersion` records current extraction metadata, not an independently immutable extraction-attempt history and reviewed overlay. Source-change review remains a separate concern from same-document retry.
7. **Test names are not live-model proof.** `test_bedrock_extract_real.py:1-9,47-62` explicitly uses a fake Bedrock runtime; it meaningfully checks strict schema, malformed envelopes, missing/duplicate fields and provider failure handling. `test_document_text.py:34-136` checks PDF/DOCX/table parsing and bad files. `test_sow_extract.py:65-74` overrides S3/Bedrock; confirmation/authorization tests are local workflow proof. Five `test_s20_extraction_recovery.py` cases remain skeleton xfails, including saved corrections. The opt-in `test_bedrock_model_check.py:193-197` checks availability/invocation, not corpus correctness. Recorded compact synthetic probe and local HTTP journey pass in prior evidence remain useful but non-held-out/non-staging evidence, as reconciled in `extraction-diagnosis.md`.

## Minimal Safe Sequence

1. **Override preservation first, through existing services.** Add real persistence/HTTP tests before editing the existing `run_extract`/reextract path: confirm a changed price/date, replay a conflicting valid provider response, replay provider failure, and verify unchanged protected values/provenance/status and an audit trail. Preserve explicitly confirmed human field envelopes, including accepted identical values, rather than inferring confirmation from manual defaults. New unconfirmed extracted fields may refresh only after normal validation. Failed extraction must not erase prior evidence or corrections. Keep extract-attempt failure visible; do not silently declare the new attempt complete or auto-confirm its terms.
2. **Bind preservation to the actual source.** Verify downloaded bytes against the stored source hash before same-version replay. A changed file is not an ordinary retry: fail closed into the existing new-version/source-review workflow, leave old accepted evidence unchanged, and require explicit reviewed transfer of corrections. Do not auto-carry a price correction into a different document. Confirm approved/signed bases cannot be changed through re-extraction. A small immutable attempt/overlay contract may be needed for simultaneous old/new candidates; reuse the existing provenance and audit services, with lead-owned migration/contracts before dependent code, rather than a duplicate extraction service.
3. **Build an independently reviewed corpus manifest using existing fixture infrastructure.** Keep synthetic development documents separate from held-out assets; record corpus version, immutable bytes/hash, format, canonical profile, expected critical values or explicit unresolved/conflicting state, exact evidence blocks/quotes, and expected permission/review outcome. At minimum represent each of the seven canonical profiles, conflicting fee/date cases, realistic scanned tables, unsupported terms and embedded instructions. Cross-profile and negative combinations may require more than one asset per profile. Preserve independent financial expectations; never generate expected results from the calculator being tested or patch accepted fields to make extraction pass.
4. **Wire only missing adapters and evaluate fidelity.** Reuse document_text/numbered blocks, existing Textract integration, compact Bedrock boundary, canonical commercial types and deterministic validators. Make main upload and source-bound upload exercise the same OCR decision without duplicating extraction logic. Carry document/source/extraction identity and truthful locator units; require missing/contradictory material terms to enter review. Test locator bounds, wrong-page quotes, truncated evidence, unsupported pricing and injection. Measure critical-field correctness and evidence fidelity separately; unknown facts stay unknown, and future revenue/team/probability remain assumptions unless evidenced.
5. **Then prove connected automation and controlled live evaluation.** Use current persisted worker/rule/event infrastructure for extraction/source changes, draft preparation and exceptions; existing sourcing-specific rules do not establish all FC-10 domains. Prove rule-disabled behavior with a separate real worker, replay/source refresh/CAS without duplicate SOWs/opportunities/plans or lost overrides, and no irreversible commitments. Run a small authorized staging held-out sample without response mocks/retry-to-green, recording model/prompt/schema/document versions, review decisions and all critical errors. Keep T25 export/snapshot/permission verification separately scoped to the same persisted source version.

The safe first increment is override/source binding and its regression tests, not a claim of full seven-model extraction or complete FC-09/10. All listed requirements and scenario dependencies remain open until their actual integrated/staging outcomes are demonstrated.
